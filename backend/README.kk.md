# ЖЭС дашбордының backend-і

[Русский](README.md) · [English](README.en.md) · **Қазақша**

Python 3.12, FastAPI, Pydantic, DuckDB. Репозиторий түбірінен бірыңғай кіру нүктесі:
`src.api:app`. Жария келісімшарт: [docs/API.md](../docs/API.md), машиналық
спецификация: [openapi.json](openapi.json).

## Біздің жұмыс аймағымыз

Дашборд backend-і HTTP API-ді, тапсырмалар кезегін, күйлерді, оқиғаларды,
нәтижелерді беруді, CSV-ді және тізбекті replay-ді иеленеді. Агент әзірлеушісі
ауа райын, белгілерді дайындауды, модельді және шешім қабылдауды жүзеге асырады.
Қосылу интерфейсі: [agent-integration.md](../docs/backend/agent-integration.md).

Әріптестің бастапқы қоймасы `src/storage.py` `ForecastStore` арқылы қолданылады.
Оның кестелері мен әдістері өзгертілмеген. Сол DuckDB файлында қосымша
`api_runs` және `api_replays` кестелері жасалады: HTTP идентификаторлары, күйлер,
шығу тегі метадеректері, ревизиялар арасындағы байланыстар және API-дің толық жауаптары.

## Іске қосу

Түбірден: `make dev` немесе `docker compose up --build`.
Толық орнату және орта айнымалылары — [README](../README.md) ішінде.

API: `http://localhost:8000/api`; Swagger: `http://localhost:8000/docs`.
Фронт үшін `http://localhost:5173` және `http://localhost:3000` origin-дері рұқсат етілген;
басқалары `RENTBOX_CORS_ORIGINS` JSON-массиві арқылы беріледі.

**Бір Uvicorn процесі және агенттің бір жұмыс ағыны** қолданылады.
HTTP сұраулары модельдің аяқталуын күтпейді. Қысқа DuckDB операциялары ортақ
lock арқылы қорғалған; агентті шақыру одан тыс орындалады. Сервер жұмыс істеп тұрғанда
осы DuckDB файлын ашатын басқа API немесе CLI іске қосылмауы тиіс.
Бірнеше процесте қатар жазу үшін басқа архитектура қажет болады.

## Тапсырмалардың жұмыс тәртібі

- POST тапсырма жазылғаннан кейін 202, жолдық ID және Location тақырыбын қайтарады.
- Қабылданған тапсырмалар мен барлық оқиғалар DuckDB-де сақталады.
- Екі турбинаның толық нәтижесі, сандық storage_run_id және қорытынды статус
  бір транзакцияда жазылады.
- Турбиналар жиыны, 24/48 реттелген сағат, 0–1 аралығындағы қуат,
  әр сағат/модельдің ауа райы шығу тегі және `as_of` сәтіндегі қолжетімділік тексеріледі.
  Previous Runs үшін бағалау `valid_time - offset * 24h + 12h` түрінде қайта есептеледі;
  белгісіз шығарылым/жариялау күндері `null` күйінде қалады. Бағалау саясаты
  ескертумен айқын белгіленеді. Оқыту мақсаттары `as_of` сәтінде қолжетімді болуы тиіс.
- Күндер уақыт белдеуімен қабылданады және UTC-ге нормаланады. Ағымдағы ForecastStore үшін
  жазар алдында tzinfo алынып тасталады; JSON-да Z қайтарылады.
- Бұрынғы input_sha256 болса, нәтиже reused_run_id арқылы қайта қолданылады.
  Хеш бірдей болғанда сандар, модель және шығу тегі сәйкес келуі тиіс;
  қайта жүктеп алу уақыты, дереккөздер реті және жергілікті source_id ескерілмейді.
  Өзгертілген кірістер жаңа revision және supersedes_run_id жасайды.
- Қайталанған POST кірістерді тексеретін жеке тапсырма жасайды. Бұл сұрау кілті бойынша HTTP
  идемпотенттілігі емес.
- Replay барлық еншілес ID-ді жасайды, содан кейін оларды 24 сағаттық қадаммен
  тізбектеп орындайды. Жеке іске қосудың қатесі келесілерін тоқтатпайды. Кем дегенде
  бір еншілес іске қосу қатемен аяқталса, қорытынды статус — failed.
- Replay шекаралары қоса есептеледі. Көкжиек толығымен сақталады, тіпті ақпан айынан тыс болса да.
- Қайта іске қосқаннан кейін queued/running failed/JOB_INTERRUPTED күйіне өтеді;
  дайын нәтижелер қолжетімді болып қалады. Автоматты түрде қайта жалғастыру жоқ.
- Кезек 128 іске қосумен, бір replay — 62-мен, іске қосу журналы — 500 оқиғамен шектелген.
  Мәндер орта айнымалылары арқылы бапталады.

Ауа райы дереккөзінің толықтығы мен түпнұсқалығын, жариялану уақытын және оқытудың
дұрыстығын агент қамтамасыз етеді. Backend берілген метадеректер мен форматты тексереді,
бірақ шығарылымның тарихи қолжетімділігі фактісін өзі анықтамайды.

v0.3 келісімшарты: `series.weather.sources` және `points[].weather_inputs`.
CSV-де әр болжам сағатына бір жол бар, бірнеше модельдің метадеректері —
`weather_inputs_json` ішінде. Бір ауа райы шығарылымы бар ескі жауаптар оқу кезінде
түрлендіріледі. [Агент пен фронтқа арналған толық ақпарат](../docs/backend/weather-provenance.md).

## Агент қосылмаған кезде

Каталог, health, деректер қорытындысы, Swagger және бұрын сақталған нәтижелерді оқу
қолжетімді. Уақыт расталмаған кезде POST
409 CONFIGURATION_REQUIRED жауабын қайтарады. Уақыт бапталғаннан кейін, агент модулі болмаса —
503 AGENT_NOT_CONFIGURED. Жасанды сәтті болжамдар берілмейді.

## Әзірлеуші командалары

```bash
make openapi
make lint
make test
```

OpenAPI дерекқорды ашпай және агентті орындамай генерацияланады.
Қолданыстағы тесттер /api келісімшартына бейімделген; осы іске асыру барысында олар
іске қосылмады. OpenAPI экспорты және статикалық талдау орындалды.
Docker құрастыруы және нағыз агентпен толық сценарий әзірге тексерілмеген.
