# Backend дашборда ВЭС

**Русский** · [English](README.en.md) · [Қазақша](README.kk.md)

Python 3.12, FastAPI, Pydantic, DuckDB. Единая точка входа из корня репозитория:
`src.api:app`. Публичный контракт: [docs/API.md](../docs/API.md), машинная
спецификация: [openapi.json](openapi.json).

## Наша область работы

Backend дашборда владеет HTTP API, очередью заданий, состояниями, событиями,
выдачей результатов, CSV и последовательным replay. Разработчик агента
реализует погоду, подготовку признаков, модель и принятие решений.
Интерфейс подключения: [agent-integration.md](../docs/backend/agent-integration.md).

Исходное хранилище коллеги `src/storage.py` используется через `ForecastStore`.
Его таблицы и методы не изменены. В том же файле DuckDB создаются дополнительные
таблицы `api_runs` и `api_replays`: HTTP-идентификаторы, состояния,
метаданные происхождения, связи ревизий и полные ответы API.

## Запуск

Из корня: `make dev` или `docker compose up --build`.
Полная установка и переменные окружения — в [README](../README.md).

API: `http://localhost:8000/api`; Swagger: `http://localhost:8000/docs`.
Для фронта разрешены origin `http://localhost:5173` и `http://localhost:3000`;
другие задаются JSON-массивом `RENTBOX_CORS_ORIGINS`.

Используется **один процесс Uvicorn и один рабочий поток агента**.
HTTP-запросы не ждут окончания модели. Короткие операции DuckDB защищены
общим lock; вызов агента выполняется вне него. Не запускать другой API или CLI,
который открывает этот же файл DuckDB, пока сервер работает.
Для конкурентной записи в нескольких процессах потребуется другая архитектура.

## Поведение заданий

- POST возвращает 202, строковый ID и заголовок Location после записи задания.
- Принятые задания и все события сохраняются в DuckDB.
- Полный результат обеих турбин, числовые storage_run_id и итоговый статус
  записываются в одной транзакции.
- Проверяются набор турбин, 24/48 упорядоченных часов, мощность 0–1,
  происхождение погоды каждого часа/модели и доступность к `as_of`.
  Для Previous Runs оценка пересчитывается как `valid_time - offset * 24h + 12h`;
  неизвестные даты выпуска/публикации остаются `null`. Политика оценки явно
  отмечается предупреждением. Обучающие цели должны быть доступны к `as_of`.
- Даты принимаются с зоной, нормализуются в UTC. Для текущего ForecastStore
  перед записью снимается tzinfo; в JSON возвращается Z.
- При прежнем input_sha256 результат переиспользуется с reused_run_id.
  Числа, модель и происхождение при одинаковом хеше должны совпадать;
  время повторного скачивания, порядок источников и локальные source_id игнорируются.
  Изменённые входы создают новую revision и supersedes_run_id.
- Повторный POST создаёт отдельное задание проверки входов. Это не HTTP
  идемпотентность по ключу запроса.
- Replay создаёт все дочерние ID, затем выполняет их последовательно с шагом
  24 часа. Ошибка отдельного запуска не отменяет следующие. Итоговый статус
  failed, если хотя бы один дочерний запуск завершился ошибкой.
- Границы replay включительны. Горизонт сохраняется полностью, даже за пределами февраля.
- После перезапуска queued/running переходят в failed/JOB_INTERRUPTED;
  готовые результаты остаются доступны. Автоматического возобновления нет.
- Очередь ограничена 128 запусками, один replay — 62, журнал запуска — 500 событиями.
  Значения настраиваются через окружение.

Полноту и подлинность погодного источника, время публикации и корректность
обучения обеспечивает агент. Backend проверяет переданные метаданные и формат,
но сам не устанавливает факт исторической доступности выпуска.

Контракт v0.3: `series.weather.sources` и `points[].weather_inputs`.
CSV содержит одну строку на прогнозный час, метаданные нескольких моделей —
в `weather_inputs_json`. Старые ответы с одним погодным выпуском преобразуются
при чтении. [Подробности для агента и фронта](../docs/backend/weather-provenance.md).

## Без подключённого агента

Каталог, health, сводка данных, Swagger и чтение ранее сохранённых результатов
доступны. При неподтверждённом времени POST отвечает
409 CONFIGURATION_REQUIRED. После настройки времени без модуля агента —
503 AGENT_NOT_CONFIGURED. Искусственные успешные прогнозы не выдаются.

## Команды разработчика

```bash
make openapi
make lint
make test
```

OpenAPI генерируется без открытия базы и без выполнения агента.
Существующие тесты адаптированы под контракт /api; при этой реализации они
не запускались. Экспорт OpenAPI и статический анализ выполнены.
Docker-сборка и полный сценарий с настоящим агентом пока не проверены.
