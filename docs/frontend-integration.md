# Дашборд и реальный backend

Windcast подключён к FastAPI: запускает агент, показывает его события,
загружает прогноз, читает историю DuckDB и скачивает CSV выбранного выпуска.
Контракт: [API.md](API.md), [OpenAPI](../backend/openapi.json).

## Запуск

```bash
./run.sh all
```

Backend обычно использует порт 8000, интерфейс — 3000. Скрипт печатает
фактические адреса и передаёт порт API в `RENTBOX_API_URL` для Next.js.
Можно открыть интерфейс через localhost или 127.0.0.1: браузер обращается
к `/api` на своём origin, Next.js проксирует запросы к FastAPI.

При отдельном запуске frontend задайте в `apps/web/.env.local`:

```dotenv
RENTBOX_API_URL=http://127.0.0.1:8000/api
```

По умолчанию используется этот же адрес. `NEXT_PUBLIC_API_URL` поддерживается
как запасное имя настройки прокси. После изменения адреса перезапустите Next.js;
при production-сборке задавайте адрес во время `next build`.
Секреты и ключи для интерфейса не нужны.

## Пользовательский сценарий

1. Дашборд загружает `/health`, `/turbines`, `/data/summary` и последние 100
   запусков `/agent/runs?limit=100`. Открытие страницы само не создаёт прогноз.
2. Пользователь выбирает турбину, первый день прогноза и горизонт 24/48 ч.
   «Рассчитать прогноз» отправляет `POST /agent/runs`.
3. Статус опрашивается раз в 1.5 секунды до `completed` или `failed`.
   Стадия, прогресс и журнал берутся из серверного ответа.
4. Готовый результат загружается из `/agent/runs/{id}/forecast`.
5. «CSV выпуска» скачивает `/agent/runs/{id}/forecast.csv`: весь серверный
   выпуск, включая обе турбины, если он был рассчитан для обеих. Переключение
   графика на одну турбину не меняет содержимое сохранённого выпуска.
6. История показывает реальные статусы и сохраняется при перезагрузке.
   «Открыть» восстанавливает параметры и загружает результат по ID. Для
   незавершённого задания возобновляется опрос, новый POST не отправляется.

При изменении даты или горизонта старый график скрывается до загрузки
подходящего расчёта. Если в выпуске есть обе турбины, можно переключать их
графики без пересчёта. Средняя мощность станции — арифметическое среднее
нормализованных мощностей, не суммарная выработка в МВт.

Переключатель «Обновить архив погоды» передаёт `refresh_weather=true`.
По умолчанию используется проверенный кэш. Этот флаг не разрешает выходить
за исторический момент `as_of`.

## Время

Время интерфейса отображается с фиксированным смещением UTC+5.
Дата в селекторе — первый день прогноза. Например, 1 февраля соответствует
`as_of=2026-01-31T18:00:00Z`; первый час — 19:00 UTC, то есть 00:00 UTC+5.
Это ежедневный сценарий текущей NOAA-модели, не текущее календарное время.

`research_mode` и отсутствие подтверждения исходных CSV отображаются в
интерфейсе. Настройка отображения времени не подтверждает часовой пояс
исходных CSV. Перед финальной оценкой всё ещё нужен ответ организаторов.

## Значения и происхождение

- `predicted_power` преобразуется из 0…1 в 0…100% только для отображения.
  CSV сохраняет серверную шкалу 0…1.
- Фактическая мощность февраля, её ошибка и интервалы неопределённости
  отсутствуют в ответе. График не строит для них линий и полос; показатели — «—».
- Скорость ветра (100 м) и температура (2 м) берутся из `wind_speed_100m` и
  `temperature_2m` точки прогноза: это тот же выпуск погоды, по которому
  посчитана мощность. Для «Все турбины» показано среднее двух турбин. Выпуски,
  сохранённые до появления этих полей, показывают «—». В `weather.sources`
  лежат метаданные источника, а не числовая погода.
- Источники, время выпуска/публикации, дата скачивания, SHA-256 и версия модели
  читаются из выбранного результата. В диалоге часа доступны ссылки на
  фактически использованные источники и оценка доступности Previous Runs.
- 3D-турбина сохранена. Мощность связана с выбранным часом; без значений ветра
  вращение не рассчитывается. Обледенение и механическая конструкция — иллюстрации.

## Ошибки и восстановление

Ошибки API показываются пользователю. Автоматического перехода на синтетические
значения нет. При потере соединения сохранённый `run_id` позволяет продолжить
опрос кнопкой «Проверить запуск» либо открыть задание из истории. После
неопределённого исхода POST сначала проверьте историю, чтобы не создать дубликат.
При уходе со страницы запросы опроса отменяются; серверное задание продолжает
работу и остаётся доступным в истории.

Неподтверждённые настройки, отсутствие агента и изменения исходных CSV
сообщаются сервером. Для незапущенного backend интерфейс предлагает обновить
состояние после восстановления соединения.

### `Method Not Allowed` при загрузке истории

Если `GET /api/agent/runs?limit=100` возвращает `405` с `Allow: POST`,
на порту API работает старая версия backend без маршрута истории.
Обновление файлов само по себе не перезапускает ранее запущенный `make run`.
Остановите этот процесс в его терминале и запустите актуальный код через
`make dev` либо `./run.sh all`, затем обновите страницу дашборда.
Для процессов, поднятых `run.sh`, остановка — `./run.sh stop`.

Локальный `run.sh` теперь следит за Python-кодом в `backend/app` и `src`.
Готовность API проверяется успешными ответами health и истории; HTTP-ошибка
больше не считается успешным запуском. После изменения `.env` или зависимостей
backend нужно перезапустить вручную. Адрес в `RENTBOX_API_URL` должен совпадать
с портом этого процесса.

## Код

- `apps/web/lib/forecast-api.ts`: типы контракта, HTTP, преобразование для графика и CSV.
- `apps/web/lib/use-forecast-dashboard.ts`: загрузка каталога, запуск, опрос, отмена и история.
- `apps/web/components/wind-dashboard.tsx`: представление результатов и состояний.
- `apps/web/next.config.ts`: прокси `/api`.
- `backend/app/api/routes/forecasts.py`: список сохранённых запусков.

При подключении frontend выполнены TypeScript, ESLint, Ruff и экспорт OpenAPI.
После исправления локального запуска проверен реальный HTTP-сценарий через
Next.js-прокси: загрузка каталога и истории, расчёт, статус `completed`,
96 прогнозных значений и CSV из 96 строк. Автотесты и браузерный сценарий
в рамках этого исправления не запускались.
