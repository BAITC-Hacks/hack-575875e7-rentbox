## P0 — работоспособность финальной версии

### 1. Обнаружен откат frontend к синтетическим данным — восстановление внесено

[README:184–210](../README.md#посмотреть-дашборд-windcast) заявляет настоящий API,
историю DuckDB, серверный CSV и помощника. В исходном снимке
`apps/web/components/wind-dashboard.tsx` снова вызывал `generateForecast`,
имитировал стадии таймером и содержал искусственный выпуск `FC-0201-001`.
Реальные API и помощник исчезли после изменения frontend в `5e8b4a7`.

**Статус после обнаружения:** основной агент восстановил API и помощника поверх
почасового воспроизведения и плавающей кнопки. Повторное чтение рабочего дерева
подтвердило импорт и вызов `useForecastDashboard`, импорт и рендер `PlatformHelper`.
Это статическое подтверждение восстановления; браузерную проверку этот аудит
не выполнял. Изменения должны попасть в итоговый коммит и push.

Риск до восстановления: несоответствие реализации заявленному сценарию,
критерии соответствия/реализации/README; первичная проверка — **п. 5.6.1**.
Само обнаружение ошибки не означает автоматическую дисквалификацию.

### 2. Нужна проверка именно финальной сборки

[README:545–550](../README.md#известные-ограничения) сообщает, что браузерный
сценарий ещё предстоит пройти; описанная чистая проверка относится к backend.
`scripts/check-clean-env.sh` проверяет подъём контейнера и health, но не расчёт,
историю и frontend. Прохождение такого скрипта не доказывает весь сценарий.

**Действие:** после объединения изменений пройти запуск из чистого клона,
расчёт, историю после перезагрузки, CSV и основной сценарий без ключей.
В README записать только фактически полученный результат.

**Формальное последствие при невозможности запуска:** недопуск к дальнейшему
отбору, дополнительные пояснения и исправления не принимаются — **п. 5.4.16,
5.6.5**. Требования самостоятельного развёртывания — **п. 5.6.3–5.6.4**.
Сама честная оговорка о непроведённой проверке не является доказанным нарушением.

## Что уже раскрыто корректно

README содержит восемь обязательных блоков, внешние материалы, участников и
AI-инструменты. Указаны отсутствие факта февраля, исследовательские настройки
времени и CPU-режим без ключей. Отсутствие публичного деплоя, февральских метрик,
онлайн-дообучения или LLM внутри численного прогнозирования само по себе не
названо основанием для штрафа. Опциональные Astra/NIM не должны становиться
обязательными для основного сценария — **п. 5.6.6**.
