## Полный текст задания

Кейс: Agentic AI для прогнозирования выработки ВЭС


Описание задачи
Необходимо разработать Agentic AI-систему для прогнозирования почасовой выработки ветроэлектростанции (ВЭС) на горизонте 24–48 часов.


Участникам предоставляются координаты и исторические данные работы ВЭС с марта 2023 года до 31 января 2026 года включительно.


Необходимо выполнить прогнозирование за тестовый период с 1 февраля 2026 года по 28 февраля 2026 года.


Предоставляемые данные
* координаты турбины 1: https://maps.app.goo.gl/iN6svMt69D5qRpFU9
* координаты турбины 2: https://maps.app.goo.gl/8UQMwsYavY6nLvFY8
* статистическое время;
* средняя скорость ветра, м/с;
* нормализированная активная мощность на стороне линии;
* средняя температура окружающей среды, °C.


Задача участников
Необходимо разработать решение, которое:
1. На основании предоставленных исторических данных строит модель прогнозирования почасовой выработки ВЭС.
2. Самостоятельно получает по координатам ВЭС из открытых источников погодные прогнозы, доступные на соответствующий момент прогнозирования.
3. Формирует прогноз выработки ВЭС на следующие 24–48 часов с почасовой детализацией.
4. Реализует процесс в формате Agentic AI, где система самостоятельно выполняет полный цикл:


получение внешних погодных данных - подготовка данных - запуск модели прогнозирования - формирование почасового прогноза - анализ результата - повторный расчёт при обновлении входных данных.


Выбор открытых источников погодных данных, ML-моделей, методов обработки данных и архитектуры AI-агента остаётся за участниками.


Участникам необходимо воспроизвести процесс, как если бы прогноз выполнялся в прошлом:
* на 31 января — сформировать прогноз на следующие 24–48 часов;
* на 1 февраля — сформировать новый прогноз на следующие 24–48 часов;
далее последовательно повторить прогнозирование в течение тестового периода.


Для каждого прогнозного периода участники должны использовать архивные прогнозы погоды, которые были доступны на соответствующий момент времени, а не фактические погодные значения, ставшие известными позднее.

## Рабочий разбор (рекомендации, не дополнительные условия ТЗ)

**Актуализировано 23.09.2026 по реализации и сохранённым отчётам.** Официальный текст и критерии выше не изменены.

- Исходные CSV содержат десятиминутную историю двух турбин с марта 2023 до 31 января 2026. Часовые цели рассчитываются только по полным часам. Факта февраля нет — качество на тестовом месяце неизвестно. [Аудит данных](../../reports/data-audit.md).
- Основная модель — ансамбль пяти MLP по погоде NOAA GFS, инференс на NumPy/CPU без GPU и API-ключей. Поиск 400 конфигураций выполнялся на CPU, RTX 5090 и Brev A6000; выбор — по ноябрю–декабрю 2025. Январь — период мониторинга разработки, не новый независимый тест. [Модель и протокол обучения](../../artifacts/gfs-model/report.md).
- Сохранены 730 операционных циклов NOAA GFS с марта 2024 по февраль 2026. Агент получает недостающий цикл по координатам или использует проверенный кэш. Инициализация и горизонт проверяются по GRIB, публикация исходных объектов — по S3 `Last-Modified <= as_of`. Сохранены происхождение и хэши; реанализ и будущая фактическая погода не используются. [Исторический протокол](../FORECAST_PROTOCOL.md).
- Агент подключён к FastAPI, очереди и DuckDB. Запрос запускает получение погоды, подготовку, расчёт, анализ диапазона мощности и резких изменений, затем сохранение результата и журнала. Есть статусы, JSON, CSV, история и последовательный replay; DuckDB обслуживает один процесс-писатель. [API](../API.md), [контроллер](../../src/agent.py).
- Пересчёт инициируется новым API-запросом; `refresh_weather=true` запрашивает обновление погоды. Агент сравнивает хэши входов: при изменении рассчитывает новую ревизию, при совпадении использует прежний результат. Постоянного фонового опроса источника нет. Изменение исходных CSV без согласованного аудита и переобучения вызывает ошибку, а не автоматическое дообучение.
- Последовательное воспроизведение завершило 29/29 выпусков с 31 января по 28 февраля, по 48 часов для двух турбин: 2784 прогнозных строки. Полные горизонты захватывают март; `in_february` выделяет целевой месяц. [Отчёт API](../../reports/agent-noaa-replay.json), [прогнозы](../../artifacts/gfs-model/february_replay.csv).
- UTC+5, начало десятиминутного интервала и выпуск в 23:00 по часам CSV (18:00 UTC) — исследовательские допущения, ожидающие подтверждения. Формула нормализации и номиналы турбин неизвестны; результат показан в исходной шкале 0–1, без заявлений о МВт/МВт·ч.
- ТЗ не задаёт конкретную метрику, порог качества, час ежедневного выпуска или формат выгрузки. MAE/RMSE и сравнение с персистентным прогнозом — выбранный командой способ оценки.
- Frontend связан с реальным API и показывает прогноз, события, историю и CSV. Отдельный сценарный симулятор использует синтетические данные и не оценивает точность конкурсной модели. Проверка финальной версии из нового чистого клона после последних изменений ещё не подтверждена; прежние проверки backend отражены в [CHANGELOG](../../CHANGELOG.md).
