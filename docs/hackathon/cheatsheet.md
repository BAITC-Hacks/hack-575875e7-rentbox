## 4. Требования к репозиторию и README (жёсткие)

README обязан содержать (п. 5.4.15, дублируется в 5.6.4):

1. описание решения и его назначения;
2. описание архитектуры;
3. используемые технологии;
4. инструкции по установке;
5. инструкции по запуску;
6. необходимые зависимости;
7. параметры окружения;
8. порядок проверки основного сценария работы.

> «README-файл должен позволять техническим экспертам понять принцип работы решения и самостоятельно выполнить его развертывание» (п. 5.4.15).

Три пункта, по которым проект вылетает без обсуждения:

- **п. 5.4.16 / 5.6.5** — если итоговую версию не удаётся запустить по инструкциям из репозитория, команда **не допускается к дальнейшему отбору**; дополнительные пояснения и исправления не принимаются. В прошлой редакции эксперты могли запросить пояснения по окружению — **этой возможности больше нет**.
- **п. 5.6.6** — проверка ключевой функциональности не должна требовать личных аккаунтов, персональных подписок или закрытых учётных записей. Используешь внешний API — приложи демо-доступ, тестовую учётку или другой способ проверки.
- **п. 5.4.9 / 5.4.11** — основная разработка только в репозитории платформы, с подтверждаемой историей.

## 5. Оценка

**Важно: критериев технической оценки в Положении больше нет.**

- Техническая оценка Проекта идёт по требованиям, критериям и правилам начисления баллов **из технического задания конкретной Задачи** (п. 5.5.1–5.5.2).
- Применяются только критерии, **опубликованные для Задачи до начала соревновательной части** (п. 5.5.3).
- Критерии **могут различаться от задачи к задаче**; для общего рейтинга результаты приводятся к единой шкале / нормализуются / ранжируются в порядке, установленном Организатором (п. 5.5.4).
- ТЗ и критерии разрабатывают постановщики задач, партнёры или эксперты; Организатор только публикует утверждённую версию (п. 5.5.5).
- **Практический вывод:** таблица «100 баллов техотбора» из прошлой редакции больше не действует. Реальный источник критериев — **текст задачи трека**. Его нужно открыть на платформе и разобрать по чек-листу в [track-energy.md](track-energy.md).

**Технический отбор (24–28.09), п. 5.6:**

- Первичная проверка: соответствие условиям, комплектность, работоспособность (п. 5.6.1), далее оценка экспертами (п. 5.6.2).
- Рейтинг формируется по критериям ТЗ Задачи; порядок формирования списка финалистов, их количество и способ сопоставления задач определяет Организатор и публикует через официальные каналы (п. 5.6.7).
- При равенстве результатов — дополнительное сравнительное рассмотрение экспертами без конфликта интересов; итог оформляется протоколом (п. 5.6.7).
- **AI-судьи** — вспомогательный инструмент предварительного анализа и ранжирования; участие в хакатоне означает согласие на такую оценку (п. 1.17, 4.2–4.4). Использование AI при оценке само по себе не основание для пересмотра (п. 5.10.4).

## 8. Обращения и апелляции (п. 5.10)

- Обращения — только от **Капитана** через официальные каналы: название команды, обстоятельства, конкретное требование, подтверждающие материалы (п. 5.10.2).
- Результаты техотбора и итоговое решение Жюри **окончательны**. Внутренней апелляции, повторной оценки и пересмотра профессионального суждения **нет** (п. 5.10.3).
- Несогласие с баллами, сравнением с другими проектами, итогами обсуждения жюри — не основание для пересмотра. Доработанная версия проекта после этапа — тоже (п. 5.10.4).
- Использование AI-судей само по себе — не основание для пересмотра (п. 5.10.4).
- Исключение: подтверждённые **арифметические, технические, редакционные ошибки и ошибки переноса/отображения данных** — Организатор вправе исправить, в том числе в протоколах (п. 5.10.6).
- Обращение не приостанавливает этапы, утверждение результатов и награждение (п. 5.10.5).
