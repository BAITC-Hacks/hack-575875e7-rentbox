# Исторический протокол прогнозирования

Главное ограничение ТЗ применяется к подготовке данных, обучению, инференсу,
агенту и оценке. Ни одна модель не получает будущую фактическую погоду или мощность.

## Момент решения

- Каждый запуск имеет отдельный `as_of`. Для февраля: ежедневно с 31 января
  по 28 февраля 2026 включительно, горизонт 24 или 48 часов.
- Текущие исследовательские настройки: `as_of=18:00 UTC`, то есть 23:00 при UTC+5;
  первая прогнозная метка — начало следующего часа. Часовой пояс CSV и смысл
  десятиминутной метки организаторы ещё не подтвердили.
- Полные 48 часов сохраняются для каждого выпуска. Часы марта остаются в истории,
  а при выгрузке только февраля фильтруются отдельно. Поздний прогноз не заменяет
  первоначальный задним числом: DuckDB хранит ревизии.

## Обучение и выбор

- Почасовая цель — среднее шести исходных измерений. Неполные часы исключаются;
  пропуски не заменяются нулевой выработкой.
- Обучение поисковых моделей заканчивается до 31 октября 2025. Их подбор идёт
  по ноябрю–декабрю 2025, без целей января и февраля.
- Дополнительная проверка устойчивости: обучение до 31 октября 2024 и оценка
  ноября–декабря 2024. Это проверка прошлого периода для уже выбранного списка,
  не независимый финальный тест.
- Для оценки января модели переобучаются на истории до 31 декабря 2025;
  для февраля — до 31 января 2026. Дни отсечки исключены целиком, с запасом.
- После первого эксперимента январь — месяц мониторинга разработки; он больше
  не называется новым нетронутым тестом. Февральских целей у команды нет.
- В `src/model.py` и `src/gfs_model.py` перед инференсом проверяется `training_data_available_until <= as_of`.
  Модель с более поздней обучающей историей для старого выпуска использовать нельзя.

## Разрешённые признаки

Архивные прогнозы ветра, температуры и давления; координаты/номер турбины;
календарь; заблаговременность; производные погодных признаков. Соседние часы
траектории допускаются только после отбора всей погоды по одному `as_of`.
Это соседние прогнозные значения, не будущие наблюдения.

Фактический ветер в `artifacts/power_curve/` используется исключительно в
диагностическом опыте. Его MAE не является качеством прогноза на сутки.
Ни реанализ ERA5, ни будущая телеметрия в прогнозные признаки не подставляются.

## Два источника и статус доказательства доступности

| Источник | Что известно | Применение |
|---|---|---|
| Open-Meteo Previous Runs, GFS/ICON | Архив фиксированных заблаговременностей; точные публикации и циклы API не возвращает | Исследовательский ансамбль `artifacts/ensemble/` |
| Операционные циклы NOAA GFS из публичного S3 | Инициализация и горизонт проверяются внутри GRIB; исходный `Last-Modified` каждого объекта должен быть не позже `as_of` | Основная модель `artifacts/gfs-model/`, 730 циклов в `data/gfs-runs/` |

Для Previous Runs применяется `valid_time - offset_days*24h + 12h <= as_of`.
Запас 12 часов — явное предположение. Не выдаём его за измеренное время публикации.
В API точные `initialization_time`/`available_at` остаются `null`, а оценка передаётся
в API-поле `available_at_estimate` с объяснением (`available_at_upper_bound` внутри модуля погоды).

Для NOAA используются циклы 12 UTC, решение 18 UTC. Файл отвергается, если
его S3 `Last-Modified` позже решения. Все 17 трёхчасовых опорных прогнозов одного
цикла (6–54 ч от инициализации) должны пройти эту проверку. Между ними линейно
интерполируются компоненты ветра, температура и давление, затем вычисляется
скорость. Интерполяция не использует наблюдений или более позднего цикла.

Сохраняются URL, время размещения, ETag, диапазоны байтов и SHA-256 каждого
использованного GRIB-поля, контрольная сумма извлечённых точек и дата скачивания.
Дата скачивания сегодня не считается исторической датой доступности.

Поиск NOAA завершён для 400 конфигураций на CPU, RTX 5090 и Brev A6000.
Основной ансамбль пяти MLP выбран по ноябрю–декабрю; январская MAE 0.15947.
Отчёт: `artifacts/gfs-model/report.md`. Через API выполнены все 29 ежедневных
выпусков февраля: `reports/agent-noaa-replay.json`.

Документация источников: [NOAA GFS в AWS](https://registry.opendata.aws/noaa-gfs-bdp-pds/),
[Previous Runs](https://open-meteo.com/en/docs/previous-runs-api).

## Агент и обновления

Контроллер проверяет входы → получает/читает архив → проверяет доступность →
строит признаки → запускает модель → анализирует диапазоны и изменения мощности →
передаёт результат backend для транзакционной записи в DuckDB.

Хеш включает фактически выбранные погодные значения, модель, исходные данные,
настройки времени и запрос. Одинаковые входы переиспользуют результат;
изменившиеся входы создают ревизию. Обновление погоды никогда не отменяет `as_of`.
После сетевой ошибки допускается сохранённый проверенный архив с предупреждением.
Если подходящей погоды или модели нет, возвращается ошибка, данные из будущего
не подставляются. Работа контроллера обозначена как `policy`; LLM-управление
не заявляется без фактического вызова LLM.
